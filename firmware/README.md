# ESP-01S 固件

目标板 ESP-01S / ESP8266、1 MB Flash。PlatformIO 固定平台 `espressif8266@4.2.1`、WiFiManager `2.0.17`、ArduinoJson `6.21.5`。串口 115200。

**仅烧录需要电脑。** 烧录完成后，首次配网、更换 WiFi、更新服务器地址和设备密钥均使用手机。配网热点名称为 `RentGate-xxxxxx`（后六位为芯片编号），密码固定为 **`RentGate888`**，配网页为 **`http://192.168.4.1`**。

## 烧录

安装 Python 3.12 与 PlatformIO，或使用 VS Code 的 PlatformIO 插件：

```powershell
python -m pip install platformio==6.1.18
pio run -d firmware
pio run -d firmware -t upload --upload-port COM3
```

将 COM3 替换为实际串口。使用烧录底座时将开关置为烧录状态；写入后切换到运行状态并重新上电。CH340 底座若只供烧录，请把 ESP 移至继电器底板运行。

产物 `firmware/.pio/build/esp01_1m/firmware.bin`，烧录地址 `0x0`。配置存储于 64 KB LittleFS 分区；首次挂载会按 ESP8266 LittleFS 默认机制初始化空分区，若挂载失败可先 `pio run -d firmware -t erase` 后重刷。擦除会清空 WiFi 和设备配置。

## 初次配网

1. 后台创建设备，保存编号和仅显示一次的 43 字符设备密钥。
2. 烧录后切换运行状态并上电，继电器先保持断开。未保存过配置时，设备自动打开热点 `RentGate-xxxxxx`。
3. 手机连接热点，密码 **`RentGate888`**，访问 `http://192.168.4.1`，点击 Configure WiFi。手机若提示“无互联网”，选择保持连接；未弹出配网页时，手动用浏览器打开上述地址。
4. 填写 WiFi 名称、密码，以及三个自定义参数：
   - Server HTTP URL：例如 `http://192.168.1.10:8080`（设备可访问的服务器 IP；不支持 HTTPS）
   - Device ID：后台登记的设备编号
   - Device key：后台生成的密钥
5. 保存后固件将自定义参数写入 LittleFS，WiFi 凭据由 WiFiManager/ESP8266 保存。WiFi 连接成功且设备参数保存有效后自动关闭热点，开始运行；重启恢复配置，无需重新烧录。WiFi 密码错误时热点保留，可以重新连接热点修改；设备参数格式错误时页面标题提示 Invalid settings，修改后再次保存。
6. 手机切回可访问后台的网络，查看设备心跳。设备每 3 秒轮询；设备与服务器需网络互通。使用局域网服务器时，换网后可能还需要更新服务器地址。

## 更换 WiFi / 修改配置（手机操作）

1. 把设备移到新网络环境，或修改原 WiFi 密码。设备上电或运行中连续约 **30 秒**连不上原 WiFi，会自动打开同名配网热点，密码始终为 **`RentGate888`**。短暂掉线先尝试自动重连。
2. 手机连接该热点，在 `http://192.168.4.1` 的 Configure WiFi 中选择新 WiFi、输入密码。原服务器地址、设备编号和设备密钥会预填；仅换 WiFi 时保留这三项即可。
3. 保存后等待连接成功，热点自动关闭，设备恢复轮询。输错 WiFi 密码时，重新连接热点继续修改；热点没有 180 秒超时限制。
4. 后台重置密钥后，设备收到 401 会自动打开热点，手机更新密钥并保存即可。若要修改服务器地址等参数但设备仍连着 WiFi，可暂时关闭原路由器 WiFi，等待约 30 秒进入配网（修改后恢复原 WiFi），全程无需接电脑。

热点无人连接时，设备每约 30 秒尝试连接已保存的 WiFi；原网络恢复且配置有效后会自动关闭热点。手机已连接热点时暂停主动重试，方便填写配置。自动配网不清除设备参数、不重置后台放行记录，也不取消或延长已有运行倒计时；配置完成后仍可能按未到期放行恢复通电。

串口字符 `c` 仅保留为开发调试入口：先关闭继电器再打开热点，不是日常配网的必要步骤。

## 继电器引脚

默认 `GPIO0`，**低电平吸合**，适配常见 ESP-01S 单路继电器底板。不同底板可能用不同有效电平，先查看实物说明，再在 `platformio.ini` 修改 `RELAY_PIN` / `RELAY_ACTIVE_LEVEL` 并重编译。

固件在设置输出模式前先写断开电平，首次启动及初次配网默认断开；运行中断网自动配网保持原倒计时，到期断开。GPIO0 是启动引脚，硬件上电瞬间状态无法仅靠软件完全消除，实物需要验证。不要使用串口 GPIO1 作为继电器输出（启动日志会改变电平）。

先用 5V 单独供继电器底板，只观察指示灯/吸合声完成联调。ESP 芯片为 3.3V 器件，请区分底板 5V 输入与 ESP 管脚。220V 改装应由具备资质的人员完成；控制板供电常供电，不经过被控继电器，负载使用 COM/NO 常开触点。

## 断网与计时

- 拉到 `on` 后用 `expire_ts - server_ts` 算剩余时间，扣除本次往返延迟，不需要 NTP。
- 相同到期时间的反复响应不会重置本地计时。
- Ticker 回调只关闭 GPIO，在主循环执行 HTTP 时也能到期断电。主循环同时用单调时钟兜底检查；`millis()` 溢出也不会延长放行。
- 网络错误、超时、错误 JSON、401 不会新开机或延长已运行时长；已有倒计时继续，到期关闭。
- 重新上电先关闭继电器，再从服务器取仍有效的指令；不会把 Flash 内的旧运行状态当作开机凭据。

固件编译能验证依赖、语法及 Flash/RAM 容量，实物才能验证供电、启动瞬态、极性、配网和最终继电器动作。
